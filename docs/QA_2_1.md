# Laporan QA — Leinz Lens Studio 2.1.0 / MySQL 5.7.24

Tanggal pemeriksaan: **4 November 2026**. Laporan ini mencakup perubahan Manage,
model CT/ET, rendering, persistensi seluruh master, dan paket instalasi versi 2.1.
[QA versi 2.0](QA_MYSQL57.md) dipertahankan sebagai catatan historis.

mencakup 30 berkas JavaScript, referensi aset HTML, dan JSON katalog.

## Pengujian MySQL nyata

Lingkungan yang dijalankan: Linux x64, Node.js 24.22.1, npm 11.9.0,
mysql2 3.24.6, dan **MySQL Community Server 5.7.24**. Versi database diperiksa
melalui `SELECT VERSION()`. InnoDB, utf8mb4_unicode_ci, dan strict SQL mode
termasuk ONLY_FULL_GROUP_BY digunakan. Database uji terpisah dari produksi.

Arsip runtime resmi: `mysql-5.7.24-linux-glibc2.12-x86_64.tar.gz`, 644.930.593 byte.
Checksum MD5 arsip cocok dengan referensi resmi
`075dccd655e090ca999e2c8da3b67eb7`. Binary dan kredensial QA tidak termasuk paket.

**24 kelompok integration test lulus**, dilanjutkan **satu pengujian persistensi
setelah proses mysqld dihentikan dan dimulai ulang**. Pemeriksaan mencakup:

- Migrasi instalasi baru dan upgrade skema enam tabel 2.0 menjadi tujuh tabel
  2.1 tanpa menghapus akun, katalog, SKU, draft, atau riwayat.
- Ketiga katalog SQL memiliki isi kanonis yang identik dengan aset seed;
  SHA-256 dibandingkan untuk setiap katalog, bukan hanya jumlah baris.
- Tambah/ubah/arsip semua jenis master, termasuk profil optik dan Unicode.
- Satu transaksi untuk material, shape, tint, dan revisi bersama.
- Kegagalan SQL nyata melalui trigger pada update tint menggagalkan seluruh
  transaksi; perubahan material/shape sebelumnya dan revisi ikut rollback.
- Pembacaan terkini dari instance store kedua, bootstrap, dan route aset
  terautentikasi. Konflik revisi 409 melindungi perubahan sesi lain.
- Seed berulang mempertahankan master yang telah diedit dan dokumen pengguna.
- Login/sesi, CSRF/Origin, isolasi akun, input rusak, ukuran body, route privat,
  dan pesan database tersanitasi tetap tercakup.
- Semua master dan profil optik bertahan setelah restart aplikasi dan database.

## Pemeriksaan browser versi 2.1

QA dilakukan pada preview mode browser. Alur berikut dijalankan dari kontrol UI:

- Navigasi Studio → Manage, tab Blank / Raw Material, Frame Shape, Manage Tinting,
  Master SKU, dan lembar acuan warna di dalam Manage Tinting.
- Membuat produk QA, menambahkan blank Ø80/BC4 dengan CT bahan 8 mm dan ET bahan
  12 mm, serta rentang SPH/CYL/ADD.
- Menyimpan profil finishing blank dengan minimum CT 1,2 mm dan ET 1,3 mm.
- Membuat shape preset 52 × 46 mm dan tint gradient dengan acuan digital manual.
- Data tetap tersedia setelah halaman dimuat ulang. Produk, shape, blank dan
  tint hasil Manage langsung tersedia di Studio.
- Memilih blank baru memperbarui CT menjadi 1,20 mm pada kedua mata pilihan A;
  CT/ET bahan tetap ditampilkan sebagai data mentah yang terpisah.
- Preview gradient, perbandingan pasangan A/B, Rimless dan tangkai tersembunyi
  diperiksa secara visual. Tepi kontinu, dimensi dan CT dekat lensa, serta
  penunjuk ketebalan maksimum tetap terbaca.
- Override konsultasi minimum CT 1,3 mm diterapkan pada kedua pilihan; nilai
  0,1 mm ditolak tanpa mengubah hasil model. Mematikan override memulihkan profil
  master/default. Tidak ditemukan error aplikasi pada log browser; pesan extension
  browser di luar aplikasi tidak dihitung sebagai error source.
- Arsip dan aktivasi kembali tint diuji. Ekspor JSON seluruh master berhasil
  diunduh dan format trl-master-catalogs/1.0 diperiksa.

Data QA hanya dibuat dalam penyimpanan browser preview lokal; aset seed paket
tetap berisi master asli. QA visual kedua dilakukan secara independen terhadap
screenshot yang sama. Tidak ditemukan cacat rendering material pada tampilan itu.

### Batas pengujian UI

Pemilih file impor pada cloud browser tidak menyelesaikan alur file chooser;
impor JSON seluruh master melalui browser belum dinyatakan lulus end-to-end.
Validasi, tinjauan perubahan, dan penyimpanan impor tercakup pengujian otomatis.
Inspeksi handler tidak menemukan pembatalan aktivasi native input/label.

CRUD master pada mode MySQL diuji melalui API nyata beserta autentikasi, sesi,
CSRF dan database. Alur UI login sampai CRUD pada mode MySQL tidak diklaim
telah diuji manual sepenuhnya. Node.js 22, Windows, Nginx/systemd dan lingkungan
server perusahaan belum dieksekusi dalam QA ini.

## Ketepatan model optik

18 pengujian model membandingkan sag sferis dan torik terhadap persamaan
independen; memeriksa daya back vertex di dua meridian, pencarian CT yang
memenuhi batas ET, konversi kurva 1.530/radius, transposisi silinder, gradien
numerik, ekstrem tepi, desentrasi dan domain tidak valid.

Tidak ada pengali yang memaksa hasil 10–20% lebih tipis. Minimum CT/ET dan
geometri permukaan menentukan hasil. Contoh dalam [model optik](OPTICS_MODEL.md)
menunjukkan CT 1,5 → 1,2 mm turun 20%, sedangkan ET pada resep yang sama turun
sekitar 8,15%. Contoh tersebut adalah hasil model, bukan validasi produksi.

Ketepatan terhadap Lensware/lensa nyata belum dapat dibuktikan tanpa konvensi
BC supplier, desain permukaan, batas proses/pemasangan dan hasil ukur lensa
finish. Asferis/freeform, progresif, prism, bevel/groove/drilling, ray tracing
penuh, VLT/coating serta stok aktual belum dimodelkan atau diverifikasi.

## Paket instalasi

ZIP diekstrak ke folder kosong yang terpisah dari checkout. `npm ci` memasang
12 package dari lockfile; `npm run build` dan `npm test` selesai dengan exit 0.
Source hasil ekstraksi kembali lulus 121 pengujian bernama serta suite assertion
blank/viewer. MySQL **5.7.24** kemudian lulus 24 kelompok integration test pada
database uji baru, dilanjutkan pengujian persistensi setelah restart mysqld.

Entrypoint **`npm start`** benar-benar dijalankan dari hasil ekstraksi. Halaman
HTML merespons 200; `/api/health` melaporkan versi **2.1.0**, databaseVersion
**5.7.24**, dan **ready: true**. Konfigurasi runtime menyatakan mode MySQL.
Sebanyak **103 hash SHA-256** kode, konfigurasi, SQL dan aset dalam
`RELEASE_CODE_SHA256.json` cocok sebelum dan sesudah pengujian. Paket akhir hanya
menambahkan dokumentasi/log QA; kode yang diuji tidak berubah.

Paket berisi frontend, server, SQL, lockfile, contoh konfigurasi dan panduan.
Tidak memuat node_modules, binary MySQL, environment berisi rahasia, database QA
atau screenshot browser. Log tersanitasi tersedia dalam `docs/qa-results/2.1/`:

- `npm-ci.txt`, `npm-build.txt`, `npm-test.txt`.
- `mysql-integration.txt`, `mysql-restart.txt`, `npm-start.txt`.

Satu peringatan npm berasal dari konfigurasi `http-proxy` pada environment QA;
konfigurasi tersebut tidak dikirim dalam paket. Tidak ada kegagalan dependency,
error sintaks/build, assertion gagal, atau kegagalan startup dalam pemeriksaan
yang dijalankan. Kredensial/host database perusahaan tidak diberikan, sehingga
laporan ini tidak mengklaim instalasi sudah dilakukan di server perusahaan.

Hasil QA berlaku pada cakupan dan lingkungan yang disebutkan, bukan jaminan
bahwa seluruh kombinasi input dan server yang mungkin bebas dari bug.
